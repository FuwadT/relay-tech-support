## User outcome

## Implementation scope

## Deliverable

## Acceptance checks
- [x] **Observable expected behavior**: Done when incomplete data displays clearly.
- [x] **Relevant failure behavior**: Handled gracefully with controlled recoverable errors; invalid requests rejected and progress not lost.

## Verification evidence
- Implemented `compareMeasurements` in `lib/diagnostics.ts` producing `improved`, `worsened`, `unchanged`, or `incomplete` directions. Missing measurements remain `incomplete` with null difference.
- Built comparison table in `components/tech-support-app.tsx` with direction badges and explicit disclaimer: *"Differences reflect user-reported measurements. Observable improvement does not prove causality or guarantee full system stability."*
- Tested in `tests/diagnostics.test.ts` with passing assertions for launch time improvement (-15s), CPU degradation (+10%), and incomplete memory state.

## Known limitations
Comparisons represent correlation in user-reported readings, not automated system verification.
