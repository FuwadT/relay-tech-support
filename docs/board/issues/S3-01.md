## User outcome
Users are asked for well-defined, optional baseline metrics without missing data being falsified as zero.

## Implementation scope
Specify units, collection instructions, and optional fields for each category.

## Deliverable
Specify units, collection instructions, and optional fields for each category.

## Acceptance checks
- [x] **Observable expected behavior**: Done when missing measurements remain unknown rather than becoming zero.
- [x] **Relevant failure behavior**: Handled gracefully with controlled recoverable errors; invalid requests rejected and progress not lost.

## Verification evidence
- Implemented `measurementDefinitions` in `lib/diagnostics.ts` with 4 metrics per category (Performance: app launch seconds, CPU %, Memory %, Free storage GB; Network: Download Mbps, Upload Mbps, Ping latency ms, Wi-Fi bars).
- Unit test passed in `tests/diagnostics.test.ts` verifying all metrics have id, label, unit, and instructions.
- Runtime E2E test `scratch/test_runtime_e2e.py` Test 7 confirmed missing values remain `None`/`null` without defaulting to 0.

## Known limitations
Pilot scope restricted to Windows 11 performance and home Wi-Fi categories.
