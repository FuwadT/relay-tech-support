## Release blockers

1. **P1 — Trusted collector download includes attacker-controlled shell source.** Uncommitted `app/api/collectors/[platform]/route.ts:17–27` interpolates arbitrary query `caseId` and `callbackUrl` into double-quoted PowerShell/bash assignments. A pure call to `GET` with an Ubuntu URL whose `caseId` is `$(printf REVIEW_MARKER)` returned HTTP 200 and `export RELAY_CASE_ID="$(printf REVIEW_MARKER)"` in the script. This would run substitution if the user followed the download/run instructions; the reproduction only inspected the returned string. Windows assignments also precede the required script parameter declaration. Remove dynamic source interpolation; use reviewed static scripts and separately validated data. Do not render user-controlled executable source.

2. **P1 — Catalog can signal an entire process group and includes irreversible deletion.** Committed `lib/enterprise/remediation-catalog.ts:190–197,258–265` defaults missing PID to zero and accepts any numeric PID; `validateRemediationProposal` accepts unchecked parameters at line 365. Safe rendering reproduced `kill -15 0` on macOS and Ubuntu, while a proposal with `pid:-1` validated successfully. The uncommitted UI at `components/enterprise-chat-view.tsx:405–424` selects a process-close action for every nonempty findings array, passes `targetProcess` but no PID, and renders that script at lines 1191–1211. Even an all-unknown snapshot generates an information finding, so it can select this unsafe action. The Windows action at catalog lines 72–102 recursively force-deletes temporary files and explicitly says they cannot be restored; this violates the approved reversible-only scope. Remove destructive actions, reject incomplete or invalid target parameters at creation/validation/render boundaries, and require target identity/ownership checks. System DNS scripts suppress failure and report success without establishing a permitted non-elevated operation; keep them unavailable until proven.

3. **P1 — Callback collection is an unauthenticated echo, not a saved case upload, and sends before preview.** Uncommitted `app/api/cases/[id]/telemetry/route.ts:7–28` accepts any ID, has no identity/tenant/case lookup, and returns `ok:true` with the submitted telemetry without storing it. CORS permits any origin. The UI polls a GET at `components/enterprise-chat-view.tsx:379–397`, but the route implements only POST and OPTIONS, so callback uploads can never reach the displayed investigation. `enterprise/collectors/windows.ps1:154–158` posts automatically to arbitrary `RELAY_CALLBACK_URL` with no upload preview, destination binding or single-use authorization. Remove the callback transport from this release; future ingestion must use the enterprise identity/case boundary and explicit reviewed upload consent. A successful echo must never be called persistence.

4. **P1 — Assistant tool authorization cannot enforce requester ownership and invents missing data.** `lib/enterprise/assistant-tools.ts:126–158` receives organization and role but no authenticated user ID, never uses role, and returns any case in the organization. A pure call with requester context and another requester's same-organization case returned its title and private description. With no lookup it manufactures a successful summary; `relay_get_diagnostic_report_meta` at lines 184–199 returns success for a nonexistent case and never calls lookup. Require authenticated user/session scope and owner-aware server lookup for every case tool; missing data/configuration must fail closed. Schema formatters alone do not constitute authenticated external-assistant integration.

## Incorrect completion and product claims

5. **P1 — Enterprise cases/conversations and execution are presented as completed without persistence or execution.** At committed `components/enterprise-chat-view.tsx:282–315` and uncommitted lines 595–629, authorization only creates a random case object in React state. There is no v2 case-create request or saved conversation. Reload loses the entire case. Default organization/user values at committed lines 151–154 are fixtures. The committed “Execute Remediation Locally” button only appends an execution-reported message; it does not execute or obtain an actual user report, yet promises status will update. The latest uncommitted UI removes that misleading execution button, but still invents the case. Keep an explicit unsaved preview until an authenticated create/read/message round trip passes, and distinguish script display, explicit user report and follow-up evidence.

6. **P1 — AI adapters and ticket delivery are stubs, not tested integrations.** `lib/enterprise/ai-provider-adapter.ts:219–226` creates then immediately clears a timer and always returns deterministic fallback: the enabled/credentialed/allowlisted path makes zero fetch calls. There are no provider requests or durable budget reservations. `lib/enterprise/ticket-connectors.ts:149–208` returns randomized external IDs without network access or durable storage; repeating the exact same outbox item/idempotency key produced two different fake ServiceNow INC IDs. `idempotencyKey` is never enforced during dispatch. `approvedSummary` is merely a caller-supplied string, not recorded technician approval. Make unavailable adapters fail explicitly, confine simulations to test infrastructure, and require genuine server-side approval/outbox/provider receipts before delivery claims. E6-01, E8-01 and E8-02 remain in progress.

7. **P1 — Model-output prose bypasses the claimed executable-action boundary.** At `lib/enterprise/ai-provider-adapter.ts:83–129`, a few regex terms are denied but arbitrary unbounded technicalSummary text is accepted without evidence validation. The pure validator accepted a summary instructing `powershell -Command "Remove-Item C:\\data -Recurse -Force"`. This output is text rather than executed code, but it can give destructive instructions to the customer. The path also silently drops invalid checks rather than rejecting the response. Before live AI enablement, separate bounded factual explanations from catalog actions, validate evidence references and exact structured fields, and reject unsupported actionable prose. Regex filtering is not a substitute for that contract.

8. **P2 — Reports and explanation copy overstate provenance, retention and missing evidence.** The shared report exports optional `technicianNotes` at `lib/enterprise/diagnostic-report.ts:72,342–347`; a pure test confirmed the internal marker appears in the HTML. Current UI omits the option, so this is a shared-export boundary defect rather than an observed current-user leak. A customer export should have no staff-note input; any staff artifact needs a separate authorized path. The report labels all non-synthetic data as device telemetry and promises 30-day retention at lines 267,352 although retention/deletion/storage are not implemented. Committed UI treats null DNS as failed and relabels pasted synthetic data as collector data; the uncommitted UI improves these two cases. New `lib/enterprise/findings.ts` explanations still say unknown memory is “within comfortable operating limits,” unknown disk has “sufficient” headroom, and synthetic CPU is “confirmed,” while process null CPU becomes zero. Preserve source/unknown semantics and condition all conclusions on validated observations.
